How to Set Up a 24/7 Paper Minecraft Server (2026)

Last updated: November 2026 · About 18 minutes to read · For server owners 16 and older

A home PC under a desk will run a world for friends until the first thunderstorm of redstone farms, a power blink, or a flood of traffic you never asked for. This is the install I use when that setup has to become a server that stays online: Paper on a KVM VPS, a heap that leaves the operating system room to breathe, and flags taken from the Paper project rather than a forum paste from 2019.

Written by Matthew Coder, editor of Minecraft Web. I wrote this for people moving a laggy home-hosted world onto a VPS they actually control. The commands are the Ubuntu 22.04 path with Java 21 (Temurin or OpenJDK) and Paper 1.21 or newer. The JVM block is Aikar’s flags as published by PaperMC, not a private fork. I revise this page when Paper or Java changes the recommended set. Minecraft Web is an independent fan project and is not affiliated with Mojang Studios or Microsoft.

Why Paper, and not Vanilla or Realms

Paper is a drop-in replacement for the official server jar. You still run a Java world. Players still join with the matching Java version. What changes is the server tick. Paper carries years of patches to hoppers, redstone, mob spawning, and the way chunks stay awake. On a survival world with farms, that work is often on the order of 30 to 50 percent less CPU than the same world on Vanilla. The number moves with your farms, your view distance, and your plugins. Use it as a planning figure, not a coupon.

Vanilla is fine for two people who never build an iron farm. It is a poor default for a community that will be online while you sleep. The main thread still has to finish every tick in 50 milliseconds. Vanilla spends more of those milliseconds on work Paper has already shortened.

Realms is the opposite trade. Mojang hosts it, backups exist, and you do not open a port on your router. Java Realms is a small friend list, not a community: you do not install plugins, you do not pick the hardware, and you cannot raise the player cap into the twenties with a voice chat plugin and a land-claim mod. If the server is a weekend world for a household, Realms is the least work. If you want permissions, claims, a discord link plugin, or more than a handful of regulars, you have already outgrown it.

Home hosting fails in three dull ways. Your IP is your home IP, so a traffic flood arrives at the same connection your family uses. A laptop that sleeps is not a 24/7 server, and a desktop that stays awake is an electricity bill plus a disk that will fill with crash logs. Port forwarding works until the router reboots and the lease changes. None of that is dramatic. It is why the world is “up” only when you are at the machine.

Spigot sits between Vanilla and Paper. It runs Bukkit plugins, which is what most communities need, but Paper is the build those plugins are tested on in 2026. Start on Paper unless a specific plugin still demands a Spigot jar. Fabric and Forge are a different product: they are mod loaders, not a faster Vanilla. Do not size a modpack with Paper numbers.

RAM, CPU, disk, and bandwidth

Minecraft Java does not scale the way a web server does. The world tick runs on one thread. Extra cores help the garbage collector, the operating system, and a backup job. They do not make the main loop twice as fast. When you compare VPS plans, read the single-core clock, not the badge that says “8 vCPU.” A modern 3 GHz core with the heap sized correctly will beat an older 8-core plan whose fastest core is sitting under 2.4 GHz and sharing a noisy neighbor.

RAM is the number people buy first, and it is the number they overbuy. The heap has to hold loaded chunks, entities, and plugin data. It does not have to hold the entire world. A world on disk can be 8 GB while the live set is 3 GB, if view distance is sane and you pre-generated the map so new players are not generating terrain during peak hour.

ServerPlayersMinimum RAMComfortable RAMDisk
Vanilla, no farms2–52 GB3 GBNVMe
Paper, light plugins10–204 GB6 GBNVMe
Paper, busy survival, claims, discord, a few farms20–406 GB8 GBNVMe
Forge or Fabric, light mod set5–106 GB8 GBNVMe
Large modpack (FTB, ATM, and the like)5–158 GB12 GBNVMe

Those figures are the machine total, not the -Xmx value. Leave 1 to 1.5 GB for the operating system and for memory Java uses outside the heap. On an 8 GB VPS, set both -Xms and -Xmx around 6.5 GB. On a 4 GB VPS, 2.5 to 3 GB of heap is the honest ceiling. If you hand Java the entire VPS, the kernel’s out-of-memory killer will stop the process at the worst moment, usually while a new chunk is saving.

Storage is not optional polish. Chunk I/O happens when players move, when the world saves, and when someone flies with an elytra. A SATA SSD is acceptable for a quiet world. A spinning disk is not: players see multi-second “loading terrain” stalls, often 3 to 5 seconds, because the main thread is waiting on the disk. Buy NVMe. Twenty gigabytes is enough for a new survival world plus a few backups on the same disk; keep older backups somewhere else so a full disk cannot stop the server from saving.

Bandwidth is smaller than people fear. A normal Java player is on the order of 50 to 150 KB/s while moving through already-generated terrain. Ten people online at once is roughly 1 to 1.5 MB/s if they are all traveling. A heavy month of that, all day, lands around 3 to 4 TB. Most VPS plans include that. The spike that hurts is not ten friends. It is a map download for a new player, or a badly configured voice chat, or someone generating terrain at high speed. Pre-generate, and the bandwidth graph stays boring.

VPS, game panel, or the PC at home

There are three places this world can live. They are not the same product with different logos.

Typical monthly costPower only, often $10–25 hiddenAbout $10–25About $5–40$40 and up

DDoS protectionNone, unless you add a proxyUsually includedDepends on the hostUsually included on the big hosts
Noisy neighborNoReal risk. Your tick shares a nodeLow on dedicated vCPU, real on cheap oversold plansNo
Skill you needRouter, firewall, and being awakeA control panelLinux, systemd, updatesThe same as a VPS, with more hardware

A shared game host is the right purchase when you want plugins but you do not want a shell. You pay for someone else to restart the jar and to absorb junk traffic. The limit shows up as lag you cannot explain: another customer’s modpack on the same CPU, a disk that is not yours, a panel that will not let you set -Xms equal to -Xmx. If the host will not tell you the processor or whether the disk is NVMe, assume the cheap plan is oversold.

A KVM VPS with a dedicated vCPU is the point where a growing server should sit. You get a real Linux system, you choose the Java version, you read your own timings, and the monthly price is still in the range of a game-host plan once you pass 4 GB. Virtualization still exists — a “vCPU” is not a pin on a motherboard — but KVM does not share the kernel with the neighbor the way a container on a sloppy host can. Read the plan. “Dedicated vCPU” and “shared vCPU” are different products that marketing sometimes blurs.

Bare metal is for a community that has already filled a solid VPS: dozens of players, a heavy modpack, or a minigame network that cannot tolerate a neighbor. It is wasted money at 15 players.

Install Paper on Ubuntu

These steps assume a fresh Ubuntu 22.04 or 24.04 VPS and a user who can use sudo. Do this over SSH. Do not run the server as root.

1. Install Java 21

Paper 1.21 and newer expects Java 21. Temurin from Adoptium is the build I prefer because the version does not drift with a surprise distro update. OpenJDK 21 from Ubuntu’s own archive is also fine.

sudo apt update
sudo apt install -y wget apt-transport-https gpg
wget -qO - https://packages.adoptium.net/artifactory/api/gpg/key/public | gpg --dearmor | sudo tee /etc/apt/trusted.gpg.d/adoptium.gpg > /dev/null
echo "deb https://packages.adoptium.net/artifactory/deb $(awk -F= '/^VERSION_CODENAME/{print $2}' /etc/os-release) main" | sudo tee /etc/apt/sources.list.d/adoptium.list
sudo apt update
sudo apt install -y temurin-21-jdk
java -version

You want a line that says 21, not 17 and not 25. If java -version still shows an older default, point the server unit at /usr/lib/jvm/ and the Temurin bin/java directly so a later package cannot silently change it.

2. Create a service account

sudo useradd --system --create-home --home-dir /opt/minecraft --shell /usr/sbin/nologin minecraft
sudo mkdir -p /opt/minecraft
sudo chown minecraft:minecraft /opt/minecraft

The server files live in /opt/minecraft. The process cannot log in. You will edit configs with sudo -u minecraft or by owning the files only while you edit them and giving them back.

3. Download Paper from Paper, not from a mirror

Open papermc.io/downloads/paper and take the build for the game version your players run. The site hands you a URL on fill-data.papermc.io. Put that URL in the command below. I am not embedding a build number here, because it goes stale the week after this page is updated.

sudo -u minecraft -s
cd /opt/minecraft
wget -O paper.jar "https://fill-data.papermc.io/v1/objects/PASTE_THE_OFFICIAL_URL_PATH"

If wget saved an HTML error page, the jar is not a jar. Check the file size before you continue. A real Paper jar is tens of megabytes.

4. Accept the EULA on purpose

Start the jar once so it writes eula.txt, then stop it. Read the EULA. If you agree, set the flag. Do not skip the read just because every guide, including this one, shows the next line.

java -jar paper.jar --nogui
# It will exit. Then:
printf 'eula=true\n' > eula.txt

5. A start script you can also call by hand

systemd will be the thing that actually stays up. A script is still useful when you want to test a flag change in the foreground and watch the log. Replace 6G with the heap from the sizing section, not with the full size of the VPS.

cat > /opt/minecraft/start.sh << 'EOF'
#!/bin/bash
cd /opt/minecraft
exec java -Xms6G -Xmx6G \
  -XX:+UseG1GC -XX:+ParallelRefProcEnabled -XX:MaxGCPauseMillis=200 \
  -XX:+UnlockExperimentalVMOptions -XX:+DisableExplicitGC -XX:+AlwaysPreTouch \
  -XX:G1NewSizePercent=30 -XX:G1MaxNewSizePercent=40 -XX:G1HeapRegionSize=8M \
  -XX:G1ReservePercent=20 -XX:G1HeapWastePercent=5 -XX:G1MixedGCCountTarget=4 \
  -XX:InitiatingHeapOccupancyPercent=15 -XX:G1MixedGCLiveThresholdPercent=90 \
  -XX:G1RSetUpdatingPauseTimePercent=5 -XX:SurvivorRatio=32 \
  -XX:+PerfDisableSharedMem -XX:MaxTenuringThreshold=1 \
  -Dusing.aikars.flags=https://mcflags.emc.gs -Daikars.new.flags=true \
  -jar paper.jar --nogui
EOF
chmod +x /opt/minecraft/start.sh
chown minecraft:minecraft /opt/minecraft/start.sh

6. systemd, so a reboot is not an outage

Write /etc/systemd/system/paper.service:

[Unit]
Description=Paper Minecraft Server
After=network-online.target
Wants=network-online.target

[Service]
User=minecraft
WorkingDirectory=/opt/minecraft
ExecStart=/opt/minecraft/start.sh
Restart=on-failure
RestartSec=15
SuccessExitStatus=0 143
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now paper
sudo journalctl -u paper -f

Restart=on-failure brings the process back after a crash. It does not restart after a clean stop, which is what you want when you are doing maintenance. 143 is the status Java returns on a normal SIGTERM, so a deliberate stop is not treated as a crash loop. Watch the first boot. Paper spends the first start rewriting configuration files. The second start is the one that should reach “Done”.

7. The port, and a word about floods

Java’s game port is TCP 25565. Open UDP as well only if you turn on query or a plugin that actually uses it. On Ubuntu’s uncomplicated firewall:

sudo ufw allow OpenSSH
sudo ufw allow 25565/tcp
sudo ufw enable
sudo ufw status

Allow SSH before you enable the firewall. I have locked myself out by doing those lines in the wrong order, and the recovery is a hosting console, not a clever flag.

A VPS public address will be scanned. That is normal. A volumetric flood is not something ufw can absorb, because the packets have already arrived at the host. Use the provider’s network protection if the plan includes it. If it does not, put a TCP proxy in front — TCPShield’s free tier, or a Spectrum-style proxy if you already pay for one — and firewall the VPS so only the proxy’s addresses can reach 25565. Do not publish the raw VPS address in your Discord after you have done that. The proxy is useless if the origin IP is in last month’s screenshot.

The JVM flags, and the two rules that matter

The block in start.sh is the set Paper documents as Aikar’s flags. People argue about individual knobs. The two rules below are the ones that show up in real outages. Get them right before you touch anything else.

Do not give Java the whole machine. -Xmx is the heap. It is not “RAM used by Minecraft.” The kernel, page cache, Java threads, and native libraries sit outside that number. If the heap plus that overhead exceeds the VPS, the out-of-memory killer sends SIGKILL. There is no stack trace worth reading, because the process did not get to write one. Leave 1 to 1.5 GB. On 8 GB of VPS RAM, 6.5 GB of heap is the top I will set. On 4 GB, stop at 3 GB and lower the view distance instead of pretending the box is bigger.

Set -Xms equal to -Xmx. A dedicated game server does not benefit from a heap that grows and shrinks. Resizing is a pause, and it happens when the server is already busy, which is when you notice it. Fixing the heap size also makes AlwaysPreTouch do its job: the process asks for all of that memory at startup. If you overshot, the server fails immediately, in front of you, instead of at prime time.

The collector is G1. -XX:+UseG1GC and -XX:MaxGCPauseMillis=200 tell the JVM to prefer short pauses over maximum throughput. A Minecraft tick is 50 ms. A 200 ms pause is already four missed ticks, which players feel as a hitch, so the rest of Aikar’s flags push G1 to start collecting earlier (InitiatingHeapOccupancyPercent=15) and to keep the young generation large enough that short-lived allocation dies there. That pattern matches a game server: lots of garbage every tick, a working set you want to stay put. You do not need to re-tune this for a 15-player survival server. You need to stop adding plugins that do work on the main thread.

G1HeapRegionSize=8M matches heaps from about 4 GB through the low teens. If you ever run a heap past 12 GB for a large modpack, move that one value to 16M and leave the rest. Do not mix in CMS flags, UseConcMarkSweepGC, or a startup line copied from a 1.8 tutorial. Those collectors are gone, and Java 21 will refuse the line or ignore the part that mattered.

I am not going to publish a single TPS figure from one afternoon and call it a benchmark. Tick time moves with the world. What I will say is narrower: on a 4 GB KVM plan, with a 3 GB heap, view-distance 7, simulation-distance 5, chunks pre-generated, and a short plugin list, a 10 to 15 player survival server is a reasonable target. If /tps falls, look at entities and farms before you look at a bigger plan. Flags do not fix a 400-villager trading hall.

A 24/7 checklist

The jar being installed is not the same as the server staying smooth. Do these before you post the IP.

  • Pre-generate the world. Install the Chunky plugin, set a radius that covers where people will actually walk, and let it finish while nobody is online. Terrain generation on the main thread is the most common “it was fine in testing” outage.
  • Cut distances. In server.properties, start at view-distance=7 and simulation-distance=5. Raise view distance only after /tps stays at 20 with your real player count. A view distance of 12 feels generous and costs you the whole CPU budget.
  • Restart on a schedule. A daily restart clears leaks in plugins you will not find this month. With systemd, a cron entry is enough: 15 5 * * * systemctl restart paper. Pick an hour your players are asleep, and say so in the MOTD. Do not also run the jar inside screen. Two supervisors will fight, and you will not know which one lost.
  • Turn on Paper’s anti-xray. In current Paper builds the switch lives in config/paper-world-defaults.yml under the anti-xray section. Engine mode 2 hides ores that are not exposed to air. It costs a little CPU and saves you a month of argument about x-ray clients.
  • Cap entities. Lower spawn-limits in bukkit.yml if farms are the point of the server but the tick is not. Paper can also use per-player mob spawns so one player’s grinder does not populate the whole dimension. A thousand mobs in one chunk will lose to any hosting plan you can afford.
  • Watch the tick, not the host’s pretty graph. /tps and /mspt tell you if the game thread is healthy. A VPS dashboard that says CPU is at 40 percent can still be a server missing ticks, because that 40 percent is one core pegged and the other cores idle. Spark, the profiler plugin, is the next step when mspt climbs and you do not know which plugin did it.
  • Notice when it is down. Point UptimeRobot, or any similar free monitor, at TCP port 25565, or at a tiny status page if you put the game port behind a proxy. Check it from outside your own network. Alert yourself. A server you only notice is down when a player complains is not a 24/7 server.
  • Backups that are not on the same disk. A nightly tar of the world, copied off the VPS, beats a snapshot you never tested. Restoring once, on purpose, is part of the setup. A backup you have not restored is a rumor.

Common mistakes

  • Setting -Xmx to the full VPS size. The process dies later, under load, with no Java error. Leave 1 to 1.5 GB, and set -Xms to the same value as -Xmx.
  • Putting the world on a spinning disk because the plan was a dollar cheaper. The lag looks like a network problem. It is the disk. NVMe is the requirement, not the upgrade.
  • Running a large modpack on 2 GB because a Paper guide said 2 GB was enough for Vanilla. It was enough for Vanilla with five players and no farms. A modpack needs the 8 to 12 GB row, and it needs a modded server jar, not Paper.
  • View distance 16 “so it looks like singleplayer.” Singleplayer is one player and a client that can hitch. Your main thread cannot hitch. Start at 6 to 8.
  • Opening the server to the internet before Chunky finishes. The first evening is everyone exploring outward at once. That is the most expensive hour the CPU will have. Spend it before launch, while the server is empty.
  • Running as root, or running inside screen and systemd at the same time. One account, one supervisor.
  • Pasting flags from a 1.12 post that still mention CMS or PermGen. Java 21 will not do what that post remembers.
  • Publishing the origin IP after you paid for a proxy. The proxy only helps if players connect to the proxy.

FAQ

How much RAM for 20 players on Paper?

Plan on a machine with 6 to 8 GB of RAM, and a heap around 4.5 to 6.5 GB. Twenty players on a pre-generated survival world with a handful of plugins fit in 6 GB of heap if simulation distance stays near 5. Twenty players plus several large mob farms fit only if you cap spawns. RAM does not replace that cap.

Can I run a Paper server on a 4 GB VPS?

Yes, for roughly 10 players, light plugins, NVMe, and a 2.5 to 3 GB heap. It is the wrong box for a modpack, for a busy event, and for view distance above 8. If the plan’s vCPU is shared and the host will not name the processor, a 4 GB plan can still feel worse than a smaller dedicated core.

Do I need a dedicated IP?

You need an address players can reach. A KVM VPS already includes one. You do not need to buy an extra “dedicated IP” add-on unless you are behind a shared game host that puts many customers on one address and separates them by port. A domain plus an SRV record is how you hide that port. The IP itself can be the one that came with the VPS.

Is a VPS better than Realms?

For plugins, player counts past a small friend group, and any control over flags or backups, yes. For a household that wants Mojang to host the world and does not want a shell, Realms is better because you will actually keep it online. Better means “fits the job,” not “more expensive.”

Which Java version?

Java 21 for Paper 1.21 and newer. Do not run a newer major release just because a VPS image shipped it, unless Paper’s download page says that release is supported. The server is pickier than the client.
